# ShopAware v0.1.0-beta.1

First installable ShopAware beta release.

This release is intended for controlled evaluation on a private network/server. It is **not yet production-qualified theft detection**. AI output is a candidate for human review, not proof of theft.

## Included

- Ultralytics YOLO26 defaults: `yolo26n.pt` detection and `yolo26n-pose.pt` pose.
- Shared pose inference with independent per-camera ByteTrack association/state.
- Multi-camera RTSP ingest with reconnect/stall handling.
- Encrypted RTSP credentials and write-only password handling.
- Admin authentication, secure cookies, session expiry/revocation and CSRF/origin checks.
- Typed normalized camera zones and heuristic multi-signal risk scoring.
- Incident snapshots plus bounded pre/post-event MP4 recording.
- Incident review workflow with notes/status and authenticated media access.
- Retention and storage-quota enforcement.
- Provider-based SMTP alerting with encrypted saved SMTP password.
- Next.js dashboard for overview, cameras, incidents, settings and training.
- Camera-selected training capture/annotation workflow.
- Reviewed train/validation/test split export to YOLO format.
- Dataset checker plus explicit YOLO26 fine-tuning/evaluation command.
- Docker CPU deployment and documented NVIDIA override path.
- Server2 production deployment profile for `shopaware.innawareucp.com` behind Apache.

## Training framework

The Training page captures clean camera frames, lets an operator draw COCO-format object boxes, requires explicit review, and exports independent training/validation/test sessions. `python -m tools.train_camera` validates the ShopAware export, fine-tunes YOLO26n and evaluates the resulting checkpoint without activating it automatically.

The training workflow trains **object detection**. It does not automatically learn theft intent, temporal activity recognition or pose from incident review statuses. A custom checkpoint must be evaluated on held-out scenes and real staged interactions before activation.

## Not yet qualified

Before calling this production-ready, qualify on the target environment with real cameras:

- at least two simultaneous independent RTSP/NVR streams;
- actual YOLO26 detection/pose checkpoint loading;
- camera reconnect and frozen-feed behavior;
- real H.264/H.265 camera decoding;
- incident evidence quality;
- SMTP delivery;
- CPU throughput and sustainable channel count;
- NVIDIA GPU latency/VRAM/channel count if GPU is used;
- false alarms and missed staged events per camera-hour;
- browser playback/codec behavior through the production reverse proxy.

## Deployment

For server2, use `docs/SERVER2_DEPLOYMENT.md` and `deploy/server2/docker-compose.yml`. The recommended layout is:

- code: `/opt/shopaware`
- persistent state/evidence/models: `/var/lib/shopaware`
- backups: `/var/backups/shopaware`
- optional Apache placeholder docroot: `/var/www/shopaware`
- public URL: `https://shopaware.innawareucp.com`

Do not place the SQLite database, encryption key or incident footage under the public web root.
