# ShopAware v0.1.0-beta.10

Beta.10 makes per-camera mode settings part of the main backend lifecycle.
Saved tuning is applied when camera runtimes are created, before inference.
SQLite schema 6 and the settings API contract are unchanged.

## Fixed

- The standard `backend:app` entrypoint now exposes the authenticated mode-settings
  routes directly. Docker and the local development command use this entrypoint.
- Camera startup, manager reload, enable/disable replacement and mode changes
  construct detector helpers with saved tuning immediately. They no longer wait
  for a later inference call to replace default thresholds and limits.
- Reconnect handling applies saved tuning to the same frame snapshot used for
  inference. The temporary processor and camera-factory monkeypatches are removed.
- `beta5_backend:app` remains a compatibility alias to the same application, with
  no import-time patching or duplicate routes.

## Validation

Five regressions were reproduced before the change: missing native routes,
compatibility import patching, manager reload, enable/disable replacement and
mode changes. Fresh-process tests also verify a schema-5 camera migration and a
schema-6 camera with saved tuning, including preserved encrypted credentials.
Existing tests cover concurrent saves, unchanged-mode state preservation,
settings validation, authorization and reconnect tuning before inference.
Three obsolete wrapper-only tests are replaced by native lifecycle coverage.

The release gate requires the exact pushed commit to pass the complete backend
suite, dashboard lint/tests/build, both CPU container builds, health/authentication
checks, actual YOLO26 detection/pose CPU inference, H.264 evidence generation,
schema verification and runtime checks after container recreation with the same
encryption key.

Saved settings persist across restarts; analytics counters remain in-memory
stream/track state. No identity recognition or cross-camera face matching is
added. Vehicle break-in and LPR results remain candidates requiring human review.

Use the [beta.10 upgrade guide](../SERVER2_BETA10_UPGRADE.md) after the exact-commit
release gate passes. Real-camera accuracy and sustained Server2 load acceptance
remain operational checks. This release does not deploy Server2 or merge main.
