# ShopAware v0.1.0-beta.7

Beta.7 completes the per-camera mode-settings candidate and corrects release
publication. The beta.5 and beta.6 tags predate the final fixes and must not be
installed. This document describes the candidate; successful qualification is
established by the push CI run and the published tag's resolved commit.

## Changes

- Independent persisted settings for Shoplifting, Vehicle break-in, LPR and
  Face Capture, with simultaneous modes still supported on each camera.
- Schema-6 migration preserves existing beta.4 cameras' effective Shoplifting
  tuning, including customized global risk and loitering thresholds.
- Saving one mode preserves unchanged modes' detector state, cooldowns and
  per-track face-capture counts. Re-saving identical settings preserves all
  detector state. Settings still apply without restarting services.
- A reconnect between frame snapshots now reapplies saved tuning before the
  first inference frame, preventing transient use of default thresholds.
- Release tag and notes are derived from `VERSION`. The publisher rejects
  mismatched branch names, checkout SHAs, missing notes and stale image versions.
- Existing lightweight and annotated tags are checked by their resolved commit;
  release metadata is not treated as proof of tag identity. Conflicting tags are
  never moved, and matching completed releases can be retried without rewriting.
- The upgrade guide requires comparing the tag's commit with the successful
  release push CI SHA before selecting the release.

## Qualification

Publication follows backend tests, dashboard lint/tests/build, both Server2 CPU
image builds, health and authentication checks, YOLO26 detection/pose CPU
inference, H.264 evidence encoding, SQLite schema 6 verification, and repeated
runtime checks after container recreation with the same encryption key.

The release gate validates the exact pushed commit. PR runs cannot publish.
Real camera footage, nighttime LPR, simultaneous cameras, and sustained Server2
CPU/storage/latency acceptance remain operational checks.

## Preserved boundaries

Customer groups, camera ACLs, training, incidents, analytics, retention,
recordings, authentication, CSRF and encrypted RTSP credentials remain in place.
Vehicle break-in and LPR results require human review. Vehicle make/model is
unclassified. Face Capture does not identify people or match faces across cameras
or visits.

Use the [beta.7 upgrade guide](../SERVER2_BETA7_UPGRADE.md) after qualification.
Rollback to beta.4 requires the complete pre-upgrade database/key backup because
schema 6 cannot be rolled back by switching code alone.
