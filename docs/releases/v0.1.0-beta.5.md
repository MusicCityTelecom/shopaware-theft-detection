# ShopAware v0.1.0-beta.5

Beta.5 carries forward all beta.4 functionality and adds validated, persisted **per-camera settings for each analytics mode**.

## Added

- Dedicated **Mode Settings** administrator page.
- Independent per-camera tuning for all four analytics modes while preserving simultaneous multi-mode operation.
- Shoplifting controls for heuristic risk threshold, scoring window, candidate cooldown and loitering threshold.
- Vehicle break-in controls for heuristic threshold, near-vehicle dwell, required access interactions, interaction interval and candidate cooldown.
- LPR controls for duplicate cooldown, minimum OCR confidence and accepted plate length.
- Face Capture controls for capture cooldown, maximum images per continuous track and minimum crop quality.
- Additive SQLite schema 6 persistence in `cameras.mode_settings_json`.
- Runtime application of saved settings without a service restart.
- Reapplication of saved settings after process/container restart, camera enable/disable and RTSP stream-generation changes.

## Preserved behavior and boundaries

- Existing beta.4 cameras retain beta.4 behavior until an administrator explicitly changes their mode settings.
- Multiple modes remain selectable on the same camera.
- Customer groups, user/camera ACLs, training, incidents, observations, retention, evidence recording, authentication, CSRF protection and encrypted RTSP credentials remain in place.
- Vehicle break-in output remains a human-review candidate, never proof of a crime.
- LPR OCR remains an unverified candidate and vehicle make/model remains unclassified.
- Face Capture remains anonymous continuous-track grouping only. Beta.5 does not add identity recognition, embeddings, watchlists or cross-camera/cross-visit face matching.

## Release qualification

The release workflow publishes this prerelease only after:

- the complete Python test suite passes;
- dashboard install, lint, tests and production build pass;
- both Server2 CPU images build and become healthy;
- actual YOLO26 detection and pose CPU inference pass;
- H.264 evidence generation passes;
- SQLite schema 6 is confirmed;
- the packaged beta.5 mode-settings endpoint is authentication-protected;
- encryption-key persistence and runtime checks pass after container recreation.

Real hotel/shop footage still requires camera-specific qualification for accuracy, false positives, nighttime plate capture, sustained CPU/storage load and event latency before operational reliance.

## Upgrade and rollback

Use `docs/SERVER2_BETA5_UPGRADE.md`. Schema 6 is newer than beta.4 schema 5, so rollback requires restoring the complete pre-upgrade beta.4 backup rather than switching code alone.
