# ShopAware v0.1.0-beta.2

First published CPU beta release for operator evaluation. This preserves the existing
beta.1 source tag and adds deployment fixes discovered during code and Server2 review.
Main and the existing bootstrap draft PR are not merged by this release.

## Install

Follow [the complete Server2 deployment guide](../SERVER2_DEPLOYMENT.md) for Ubuntu,
Docker, administrator setup, Apache/TLS, camera onboarding, backups and restoration.
The target is `https://shopaware.innawareucp.com`. Backend port 18082 avoids Server2's
existing port-18080 service. Dashboard port 18081 stays on loopback.

## Included

- Authenticated camera management, zones, live preview, candidate incidents, review,
  snapshots, pre/post-event clips, retention, encrypted credentials and SMTP support.
- Camera-selected capture, box annotation, explicit review and train/validation/test
  dataset export, with separate CPU training and deliberate model activation.
- Persistent database, key, evidence, downloaded checkpoints, datasets and training outputs.
- FFmpeg H.264/yuv420p clips with browser seeking, timestamp sidecars and encoder timeout cleanup.
- Model initialization retries, packaged version reporting and an installation check.
- Bounded API proxy requests, hop-by-hop header filtering, authenticated streaming
  and generic backend failure responses. Smaller standalone dashboard runtime.
- Consistent backups with verified checksums, required key/configuration capture and
  restart on failure; strict unauthenticated access checks and TLS renewal hook.

## Validation

- 108 Python tests passed locally with both opt-in checkpoint tests enabled.
- Five Linux operator-script tests passed: backup integrity/checksums, key-required
  failure, backend restart after backup failure, auth verification and shell syntax.
- Four dashboard proxy tests passed; ESLint and production Next.js build passed.
- Edge browser workflow passed: camera shortcut/selection, all three dataset splits,
  capture, annotation, review, ZIP export, camera isolation and logout protection.
- Edge decoded, played and sought authenticated H.264 evidence; HTTP Range returned 206.
- Real YOLO26n detection and pose CPU inference passed on bundled sample imagery,
  including pose keypoint shape and persistent tracker adapter IDs. No training run
  or store-specific model is represented as completed.

Release-branch CI includes Linux tests, dashboard checks and both CPU container builds
with runtime inference/encoding checks and container recreation. Consult the GitHub
release for the actual CI outcome; configuring a job is not evidence it ran.

## Qualification still required

This is a working beta for controlled evaluation, not a claim of deployment-qualified
theft detection. No live customer camera, SMTP delivery, long-duration load or Server2
channel capacity was qualified. Server2 was inspected read-only; containers, vhosts
and certificates were not installed. Its domain needs the certificate setup in the guide.
Issue #3 stays open for real simultaneous multi-camera evidence.

Remaining limits include uncalibrated pixel-based behavior heuristics, global model
and threshold settings, no camera credential-edit form, no frozen-image-content
watchdog, no durable alert outbox, and admin-only local accounts. CPU training
competes with other workloads; stop analysis before training on Server2.

AI outputs are incident candidates requiring human review. Upstream MIT attribution
is preserved; Ultralytics software and model licensing remain separate.
